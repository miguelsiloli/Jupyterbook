ETL → Cloud ELT Migration & Optimization

Scalable Data Infrastructure on Google Cloud Platform

Challenge & Context

Legacy pipeline faced critical scaling issues with multiple bottlenecks hampering data delivery and reliability.

  • Egress Cap: 1GB/day Blackbaze limit halted large loads/backfills.
  • DB Limit: 500MB Supabase Postgres restricted data volume & scaling.
  • I/O Thrashing: Numerous small CSVs caused network/storage bottlenecks.
  • ETL Fragility: "All-or-nothing" GitHub jobs led to frequent failures & data gaps.
  • Poor Observability: Lack of dedicated orchestration tools hindered monitoring/debugging.

Solution Approach

  1. Optimized Ingestion (GCS): Consolidated raw CSVs into Parquet files on Google Cloud Storage, reducing size/count & solving egress limits.
  2. Scalable Warehouse (BigQuery): Loaded Parquet directly into BigQuery, removing database size constraints.
  3. In-Warehouse Transformation (ELT): Re-implemented logic using BigQuery SQL (managed via dbt), leveraging its power and scalability.
  4. Decoupled Workflow: Enabled partial/differential loads and improved resilience (using orchestrator patterns).
