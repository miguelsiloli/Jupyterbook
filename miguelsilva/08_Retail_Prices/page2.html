ETL → Cloud ELT Migration

Scalable Data Infrastructure on Google Cloud Platform

Challenge & Context

Legacy pipeline facing networking/storage limitations, poor observability and pipeline breaks.

Egress Cap: 1GB/day Blackbaze limit
DB Limit: 500MB Supabase Postgres
I/O Thrashing: Small CSVs bottlenecks
ETL Fragility: "All-or-nothing" failures
Poor Observability: Limited monitoring
Solution Approach
1
Optimized Ingestion: CSVs to Parquet on GCS
2
Scalable Warehouse: Parquet to BigQuery
3
In-Warehouse Transform: BigQuery SQL via dbt
4
Decoupled Workflow: Partial loads, better resilience
